No Studio clássico, o fluxo é a lógica: cada caixinha é um estado e cada seta uma rota fixa que você precisa prever. No modelo 100% agêntico, o prompt define objetivo, regras e ferramentas — e o modelo escolhe o caminho em tempo real. Antes de entrar na parte técnica, veja a jornada acontecendo.

Cada aresta é uma rota fixa que você precisa antecipar.

O prompt define as regras

O modelo navega dentro dos limites e chama ferramentas.
  • Nova intenção é ajustar o prompt, não redesenhar.
  • Entende texto livre e áudio nativamente.
  • Tracking são eventos, decisões e tools por turno.
  • Flexível, com guardrails no lugar das arestas.
Bom para conversa real com regras de negócio fortes.
A arquitetura

Determinístico + agêntico no mesmo fluxo

Não é oito ou oitenta. O começo, onde a régua é fixa, continua determinístico. O miolo da negociação vira agêntico. E o roteamento entre os blocos leva o cliente ao destino certo.

As três dúvidas

Sem step by step, como faço tracking, doc e chamada?

Nada disso some — só muda de lugar. Deixa de estar no desenho do fluxo e passa a ser instrumentado por turno.

Tracking: de "qual bloco" para "qual decisão"

"Como é que faz tracking se não é mais step by step?"

No determinístico você rastreava por onde a pessoa passou. No agêntico você rastreia o que aconteceu em cada turno: o input, a decisão do agente, quais tools ele chamou e com quais parâmetros, e o output.

Os eventos de negócio continuam existindo — você os instrumenta como marcadores/tool calls ("acordo_confirmado", "handoff_humano"), em vez de depender de "passou pela caixinha X". Mais confiável: o evento dispara quando o fato acontece, não quando um nó é atravessado.

Cada execução vira um trace com spans (turno → tool → handoff), o que dá replay da sessão e métricas de funil sem amarrar no desenho.

Documentação: o prompt é a fonte da verdade

"Como é que faz documentação disso?"

No modelo de blocos, a documentação era o próprio canvas. No agêntico, o system prompt versionado é a documentação viva — descreve personalidade, regras de negócio, guardrails e prioridades em linguagem clara.

Ao redor dele, três artefatos completam o quadro: o catálogo de tools (nome, o que faz, schema de entrada/saída), o mapa de handoffs entre agentes, e um diagrama de intenção — não de execução — para leitura humana.

Versionamento estilo git + changelog do prompt dá rastreabilidade de "o que mudou no comportamento e quando".

Chamadas: a caixinha de requisição vira uma tool

"Como é que faz chamada, tipo integração com API?"

No Studio, uma chamada de API era um bloco fixo num ponto do fluxo. No agêntico, você declara a tool (nome, descrição, parâmetros) e o modelo decide quando chamá-la, a partir da intenção do cliente.

Você não perde controle: a tool tem contrato e validação, e as regras críticas ficam no prompt e na própria API. O agente orquestra; a lógica sensível continua no backend.

Aqui, "gerar pagamento" deixa de ser um nó obrigatório numa rota e passa a ser uma ferramenta chamada só depois do resumo confirmado — o gate amarra isso no prompt.

Tool declarada
gerarPagamento({
  tipo: "pix" | "boleto",
  parcelas: number,
  valorFinal: number
})

// o modelo chama por intenção,
// nunca antes do resumo (gate)

Conexão entre agentes: orquestrador + especialistas

"Como conecta com os agentes e tal?"

Um fluxo 100% agêntico raramente é um único agente gigante. É um orquestrador que resolve a conversa e faz handoff para agentes especializados quando a intenção sai do seu escopo.

Cada agente tem seu próprio prompt e suas próprias tools. O handoff carrega o contexto da sessão, então o cliente não repete informação.

Isso mantém cada agente enxuto e auditável, e deixa o tracking limpo: cada handoff é um span com origem, destino e motivo.

Como começar

Um caminho de transição, sem big bang

Você não precisa migrar tudo de uma vez. Dá para testar o agêntico onde ele rende mais e manter blocos onde o determinismo ainda faz sentido.

1

Escolha uma jornada aberta

Renegociação, dúvidas, atendimento — casos com conversa real e muitas variações são onde o determinístico mais sofre e o agêntico mais brilha.

2

Escreva o prompt como regra, não como rota

Objetivo, guardrails e prioridades. Declare as tools que ele pode chamar. Personalidade, regras de negócio e passos entram como estados.

3

Instrumente e observe

Eventos de negócio como marcadores, traces por turno, replay de sessão. Ajuste o prompt com base no que o tracking mostra — ciclo curto.

Para depois do novo contrato: um bom primeiro piloto é pegar um fluxo hoje 100% em caixinhas, reconstruir só ele como agente com 3–4 tools e handoffs, e rodar em paralelo. Você compara determinístico vs agêntico com dados reais antes de escalar.
